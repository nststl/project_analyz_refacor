# Вимоги до системи

## 1. Призначення

Система автоматизує ключові процеси публічної бібліотеки:

- облік **примірників** і їх доступності;
- **видачу** та **повернення** книг читачами;
- **чергу резерву** (FIFO) на популярні видання;
- **нарахування штрафів** за прострочення (алгоритм задається стратегією);
- **блокування** читачів (адміністративне та автоматичне).

Усі дані зберігаються **in-memory** — без зовнішніх баз даних. Це дозволяє зосередитись на доменній логіці, патернах проєктування та тестуванні.

## 2. Актори

| Актор | Опис |
|-------|------|
| **Читач** | Переглядає каталог, оформлює позики та резерви, повертає книги; підпадає під штрафи та блокування. |
| **Бібліотекар** | Керує читачами: блокування / розблокування, перегляд статусів і заборгованості. |
| **Система** | Застосовує правила штрафів, автоблокування та сповіщення Observer без участі людини. |

## 3. Сценарії (Use Cases)

| ID | Назва | Опис |
|----|-------|------|
| UC-01 | Видача книги | Читач бере доступний примірник; створюється позика з дедлайном; `available_copies` зменшується. |
| UC-02 | Повернення вчасно | Повернення до `due_at`; штраф 0; примірник знову доступний. |
| UC-03 | Повернення з простроченням | Штраф за календарні дні після дедлайну (Strategy). |
| UC-04 | Резерв у черзі | Читач стає в FIFO-чергу; повторний резерв тієї ж книги заборонено. |
| UC-05 | Сповіщення про наявність | Після повернення примірника наступний у черзі отримує подію (Observer). |
| UC-06 | Блокування бібліотекарем | Встановлюється `blocked_until`; нові позики недоступні. |
| UC-07 | Автоблокування | Політика блокує читача при серйозному простроченні / заборгованості. |

## 4. Бізнес-правила

| Правило | Реалізація |
|---------|------------|
| Ліміт позик | `max_concurrent_loans` (у демо-даних: **2** на читача) |
| Reference-книги | Категорія `REFERENCE` — лише читальний зал, не видаються |
| Штраф | Календарні дні після `due_at`; ставка залежить від Strategy і категорії (`RARE` ×2) |
| Черга резерву | Порядок за зростанням `sequence` |
| Автоблок | `blocking_policy.py` — пороги за днями прострочення та сумою штрафу |
| Симуляція часу | `SimulatedClock` — перемотка дати в UI для демонстрації UC-03 / UC-07 |

## 5. Нефункціональні вимоги

- Шарова архітектура (models → services → storage → web).
- GoF-патерни: **Strategy**, **Observer**.
- Інверсія залежностей через `typing.Protocol`.
- Покриття тестами ≥ 70%; SonarCloud Quality Gate у CI.
- Звіти: JUnit XML, coverage XML/HTML, артефакти GitHub Actions.
